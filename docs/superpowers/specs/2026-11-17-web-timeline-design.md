# 웹 타임라인 설계

2026-11-17. Photo Tidy의 타임라인 기능을 브라우저에서 쓰는 웹 버전.

## 목적

사진 파일을 끌어다 놓으면 지도에 머문 곳과 경로를 그리고, 날짜별 목록과 공유 이미지를 만든다.
아이폰이 없어도(맥, 윈도우) 쓸 수 있고, 링크로 다른 사람에게 줄 수 있다.

## 범위

**넣는 것**

- 사진 파일 받기(끌어다 놓기, 파일 선택). 여러 번 나눠 올리면 합친다.
- 지도: 머문 곳 번호 핀, 날짜별 경로 선.
- 날짜별 머문 곳 목록: 장소 이름, 시간 범위, 장수, 썸네일.
- 머문 곳 줄을 누르면 지도가 그곳으로 이동.
- 장소 이름 자동 붙이기, 직접 고치기.
- 이미지 한 장으로 저장(지도 + 목록).
- 전부 지우고 다시 시작.

**넣지 않는 것**

- 정리 기능(비슷한 사진 묶기, 삭제). 웹은 사진첩을 지울 수 없다.
- 하루씩 보기, 날짜 넘기기. 올린 사진 전체를 한 화면에 날짜별로 이어 보여 준다(아이폰 앱의 앨범 보기와 같다).
- 로그인, 서버 저장. 사진은 페이지를 닫으면 사라진다.
- HEIC 변환. 브라우저가 못 그리는 형식은 썸네일을 빈 칸으로 둔다.
- 사진 크게 보기.

## 기술 선택

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 뼈대 | Vite + React + TypeScript | 서버가 필요 없는 정적 사이트. 무료 호스팅에 그대로 올라간다 |
| 지도 | Leaflet + 오픈스트리트맵 타일 | 키 발급 없이 쓸 수 있다 |
| 사진 정보 | `exifr` | JPEG·HEIC의 위치와 촬영 시각을 읽는다 |
| 장소 이름 | Nominatim(오픈스트리트맵) | 키 없이 쓸 수 있다. 1초에 1번 제한 |
| 꾸미기 | 일반 CSS | 화면이 하나라 라이브러리가 필요 없다. 색은 아이폰 앱과 같은 청록 `rgb(13, 133, 122)` |
| 테스트 | Vitest(로직), Playwright(화면) | |
| 패키지 관리 | npm | |

위치는 저장소 안의 `web/` 폴더. 아이폰 앱 코드(`PhotoTidy/`, `PhotoTidyCore/`)는 건드리지 않는다.

## 구조

아이폰 앱과 같은 원칙: 판단 규칙은 화면·브라우저와 분리한다.

```
web/
├── index.html
├── package.json
├── src/
│   ├── core/          판단 규칙. 브라우저 기능을 쓰지 않는다
│   ├── services/      브라우저·외부 서비스와 이야기하는 곳
│   ├── components/    React 화면
│   ├── App.tsx
│   └── main.tsx
└── e2e/               Playwright 화면 테스트
```

### `src/core/` — 판단 규칙

Swift `PhotoTidyCore`에서 타임라인에 필요한 것만 TypeScript로 옮긴다. Swift 테스트도 같이 옮겨 같은 동작임을 확인한다.

| 파일 | 옮겨 오는 곳 | 하는 일 |
| --- | --- | --- |
| `types.ts` | `TimelineBuilder.swift`의 타입 | `Coordinate`, `TimelinePhoto`, `TimelineStop`, `TimelineDay` |
| `tuning.ts` | `Tuning.swift` | `stopRadius = 200`, 이름 요청 간격 등 |
| `timeline.ts` | `TimelineBuilder` | `distance`, `stops`, `days` |
| `timelineText.ts` | `TimelineText` | 시간 범위, 기간 글자 |
| `placeKey.ts` | `PlaceKey` | 좌표 → 캐시 열쇠(`"37.580,126.977"`) |
| `placeNameLookup.ts` | `PlaceNameLookup` | 이름 요청을 한 줄로 세우고 기억. 요청 사이 최소 간격을 지킨다 |
| `customNames.ts` | `CustomPlaceNames` | 직접 붙인 이름을 사진 id에 붙인다. 200m 물려받기와 opt-out 포함 |
| `shareOutline.ts` | `ShareOutline` | 공유 이미지에 담을 내용 |
| `mercator.ts` | 새로 만듦 | 좌표 ↔ 지도 타일·픽셀 변환, 여러 좌표가 들어가는 확대 단계 고르기 |

Swift와 달라지는 점:

- 날짜 경계는 `Calendar` 대신 시간대 이름(`"Asia/Seoul"`)을 인자로 받아 계산한다. 기본값은 브라우저 시간대.
- 사진 id는 사진첩 id 대신 `파일이름|크기|수정시각`으로 만든다. 같은 파일을 두 번 올리면 한 번만 들어간다.
- `PlaceNameLookup`에 "요청 사이 최소 간격"(기본 1.1초)을 더한다. Nominatim의 1초 1번 제한 때문이다. 시계와 기다리기 함수는 밖에서 받아 테스트에서 가짜를 넣는다.

### `src/services/` — 바깥과 이야기하는 곳

| 파일 | 하는 일 |
| --- | --- |
| `readPhoto.ts` | `File` → `TimelinePhoto`. `exifr`로 위치와 촬영 시각을 읽는다. 촬영 시각이 없으면 파일 수정 시각을 쓰고 그 사실을 표시한다 |
| `nominatim.ts` | 좌표 → 장소 이름. 실패하면 `null` |
| `storage.ts` | 받은 이름(캐시)과 직접 붙인 이름을 `localStorage`에 저장. 읽기·쓰기가 실패해도 앱은 동작한다 |
| `thumbnails.ts` | `File` → 썸네일 주소(`createObjectURL`). 지울 때 해제한다 |
| `shareImage.ts` | 공유 내용 → PNG. 타일을 받아 캔버스에 지도·핀·선·목록을 그린다 |

### `src/components/` — 화면

| 파일 | 하는 일 |
| --- | --- |
| `DropZone.tsx` | 끌어다 놓기와 파일 선택 |
| `TimelineMap.tsx` | Leaflet 지도, 번호 핀, 날짜별 선 |
| `StopList.tsx` | 날짜 구분 줄과 머문 곳 카드 |
| `StopCard.tsx` | 번호, 이름, 시간·장수, 썸네일 줄, 이름 고치기 |
| `useTimeline.ts` | 화면 상태(사진, 머문 곳, 이름)를 묶는 훅 |

## 데이터 흐름

1. 사용자가 파일을 놓는다 → `readPhoto`가 파일마다 위치·시각을 읽는다(읽는 동안 진행 표시).
2. `timeline.days(photos)`가 날짜별 머문 곳을 만든다.
3. 화면에 지도와 목록을 그린다. 이름은 "직접 붙인 이름 → 받은 이름 → 장소 N → 위치 정보 없음" 순으로 정한다.
4. 위치가 있는 머문 곳마다 `placeNameLookup`이 이름을 하나씩 받아 온다. 받는 대로 화면에 반영하고 저장한다.
5. "이미지로 저장"을 누르면 그 순간의 내용으로 `shareOutline`을 만들고 `shareImage`가 PNG를 만들어 내려받게 한다.

## 화면 구성

위에서 아래로 한 줄. 넓은 화면(900px 이상)에서는 지도를 왼쪽에 고정하고 목록을 오른쪽에 둔다.

- 머리말: 제목, 기간·장수 요약, "이미지로 저장", "전부 지우기"
- 사진 놓는 영역: 사진이 없을 때는 크게, 있을 때는 작게("사진 더 올리기")
- 지도(위치 있는 머문 곳이 하나도 없으면 안내 글)
- 날짜별 목록
- 맨 아래 안내: 사진은 브라우저 밖으로 나가지 않고, 장소 이름을 받을 때 좌표가 오픈스트리트맵 서버로 전송된다는 것. 지도 저작권 표시.

## 문제 상황

| 상황 | 동작 |
| --- | --- |
| 위치 없는 사진 | 시간순으로 머문 곳에 넣는다. 위치 있는 사진이 하나도 없는 머문 곳은 "위치 정보 없음" |
| 촬영 시각 없는 사진 | 파일 수정 시각을 쓴다. 요약 줄에 "촬영 시각이 없어 파일 시각을 쓴 사진 N장" |
| 사진이 아닌 파일, 읽기 실패 | 건너뛰고 "읽지 못한 파일 N개"로 알린다 |
| 브라우저가 못 그리는 형식(HEIC 등) | 썸네일 자리에 빈 칸. 타임라인에는 포함 |
| 이름 받기 실패·인터넷 없음 | "장소 N"으로 둔다. 실패는 기억하지 않는다 |
| 머문 곳이 40곳 초과 | 공유 이미지에는 40곳까지만 담고 "외 N곳"을 적는다(아이폰 앱과 같다) |
| 공유 이미지의 타일 받기 실패 | 지도 없이 목록만으로 이미지를 만든다 |

## 테스트

- **로직(Vitest)**: `core/` 전체. Swift 테스트(`TimelineBuilderTests`, `TimelineTextTests`, `PlaceNamesTests`, `PlaceNameLookupTests`, `ShareOutlineTests`)를 옮기고, `mercator`와 최소 간격 테스트를 더한다. 테스트를 먼저 쓴다.
- **사진 읽기**: `scripts/make-timeline-samples.swift`로 만든 샘플 6장(위치·시각 포함)을 테스트 자료로 써서 `readPhoto`가 좌표와 시각을 읽는지 확인한다.
- **화면(Playwright)**: 샘플 6장을 올리면 날짜 구분 줄 2개, 머문 곳 5곳이 나오고, 이름을 고치면 바뀌며, 이미지 저장이 PNG를 내려받는지 확인한다. 장소 이름 서버 요청은 테스트에서 가짜 응답으로 바꾼다.
- 테스트를 쓴 뒤 로직을 한 줄 망가뜨려 실패하는지 확인한다(이 저장소의 규칙).

## 배포

정적 사이트(`npm run build` → `web/dist/`). 저장소가 비공개라 GitHub Pages 무료 배포는 안 되므로 Vercel이나 Cloudflare Pages를 쓴다. 계정 연결이 필요해서 이 설계의 구현 범위에는 넣지 않고, 로컬에서 완성한 뒤 따로 진행한다.

## 알려진 한계

- 아이폰 브라우저에서 사진을 고르면 위치 정보가 지워져 넘어올 수 있다(미확인). 실제 기기로 확인해야 한다.
- 크롬은 HEIC를 그리지 못한다. 사파리는 그린다.
- 오픈스트리트맵 타일과 Nominatim은 개인이 가끔 쓰는 정도만 허용한다. 사용자가 많아지면 유료 서비스로 바꿔야 한다.
- 한국 동네 이름의 품질이 애플·카카오보다 떨어질 수 있다. 직접 고치기로 보완한다.
