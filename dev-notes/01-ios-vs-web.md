# iOS 앱과 웹의 차이

## 한눈에 보는 대응표

| 웹 | iOS | 설명 |
| --- | --- | --- |
| 브라우저 | 아이폰(iOS) | 코드가 돌아가는 곳 |
| VS Code + 터미널 | Xcode | 편집기 + 빌드 + 실행을 한 프로그램에서 |
| `npm run dev` | Xcode의 ▶ 버튼 | 빌드해서 실행 |
| 브라우저 개발자 도구의 기기 모드 | 시뮬레이터 | 맥에서 돌리는 가짜 아이폰 |
| `package.json` | `project.yml` → `.xcodeproj` | 프로젝트 설정 |
| 도메인 주소 | 번들 ID (`com.heejung.phototidy`) | 앱을 구분하는 고유 이름 |
| 배포(서버에 올리기) | App Store 심사 또는 기기에 직접 설치 | 사용자에게 전달하는 방법 |
| `manifest.json` | `Info.plist` | 앱 이름, 권한 설명 문구 등 |

## 가장 큰 차이 세 가지

### 1. 빌드해야 실행된다

웹은 파일을 저장하면 브라우저가 바로 읽지만, Swift는 **컴파일**(사람이 쓴 코드를 기계어로 번역)을 거쳐야 합니다.
그 대신 오타나 타입 실수를 실행 전에 잡아 줍니다. TypeScript의 타입 검사를 훨씬 엄격하게 한 것과 비슷합니다.

### 2. 권한을 받아야 한다

웹에서 `navigator.geolocation`을 쓰면 브라우저가 허용 창을 띄우는 것처럼, iOS도 사진첩·위치·카메라를 쓰려면 사용자 허락이 필요합니다.

- 왜 필요한지 설명 문구를 `Info.plist`에 **반드시** 적어야 합니다. 없으면 앱이 그 자리에서 종료됩니다.
  이 프로젝트는 `project.yml`의 `NSPhotoLibraryUsageDescription`에 적혀 있습니다.
- 사진첩 권한은 "전체 허용", "일부 사진만", "거부" 세 가지입니다. 앱은 세 경우를 모두 처리해야 합니다(`AppModel.access`).

### 3. 서명해야 기기에 설치된다

아이폰은 "누가 만든 앱인지" 확인된 앱만 실행합니다. 이 확인 도장을 **코드 서명**이라고 합니다.

| 방식 | 유효 기간 |
| --- | --- |
| 무료 Apple 계정 | 7일 (지나면 다시 설치) |
| 유료 개발자 계정 | 1년 |
| App Store 배포 | 만료 없음 |

웹처럼 "주소만 알려 주면 누구나 쓴다"가 안 되는 이유입니다. 시뮬레이터는 서명 없이 돌아갑니다.

## 시뮬레이터로 못 하는 것

시뮬레이터는 편하지만 진짜 기기와 다릅니다. 이 프로젝트에서 실제로 부딪힌 것들입니다.

- iCloud 로그인이 필요한 기능(공유 앨범)이 없습니다.
- 이미지 분석에 쓰는 가속 칩이 없어 설정을 따로 줘야 했습니다(`ImageAnalyzer`의 `usesCPUOnly`).
- 속도와 메모리가 실제와 다릅니다. 성능은 실제 기기에서 봐야 합니다.

그래서 "시뮬레이터에서 됐다"와 "아이폰에서 된다"는 다른 말입니다.

## 앱의 데이터는 어디에 저장되나

웹의 `localStorage`처럼, 앱마다 자기만 쓸 수 있는 폴더(**샌드박스**)가 있습니다. 다른 앱은 못 봅니다.

- 이 앱은 분석 결과와 장소 이름을 그 폴더에 JSON 파일로 저장합니다.
- 앱을 지우면 폴더도 같이 지워집니다. 사진첩의 사진은 앱 폴더가 아니라 시스템 것이라 남습니다.
