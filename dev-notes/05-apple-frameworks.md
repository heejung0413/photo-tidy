# 애플 프레임워크

프레임워크는 애플이 미리 만들어 둔 기능 묶음입니다. 웹의 브라우저 API(`fetch`, `canvas`, `geolocation`)에 해당합니다.
`import Photos`처럼 가져다 씁니다.

## 이 프로젝트가 쓰는 것

| 프레임워크 | 하는 일 | 쓰는 곳 |
| --- | --- | --- |
| SwiftUI | 화면 | `Views/` |
| Photos (PhotoKit) | 사진첩 읽기·삭제 | `PhotoLibrary*.swift` |
| Vision | 이미지 분석(비슷한 정도, 얼굴) | `ImageAnalyzer.swift` |
| MapKit | 지도 표시, 지도 그림 만들기 | `TimelineView`, `TimelineShare` |
| CoreLocation | 좌표 → 장소 이름 | `PlaceNamer.swift` |
| XCTest | 테스트 | `*Tests/` |

## Photos — 사진첩

핵심은 **사진 파일을 직접 받는 게 아니라 "사진을 가리키는 표"를 받는다**는 점입니다.

| 용어 | 뜻 |
| --- | --- |
| `PHAsset` | 사진 한 장의 **정보**(촬영 시각, 위치, 크기, 즐겨찾기). 이미지 자체는 아님 |
| `localIdentifier` | 사진의 고유 ID. 이 앱이 저장하는 것은 이 ID뿐 |
| `PHAssetCollection` | 앨범 |
| `PHImageManager` | ID를 주고 **원하는 크기의 이미지**를 달라고 요청하는 창구 |
| `PHFetchOptions` | 조회 조건·정렬 (DB의 WHERE, ORDER BY) |

알아 둘 점:

- **원본이 기기에 없을 수 있습니다.** "iPhone 저장 공간 최적화"를 켜면 원본은 iCloud에 있고 기기에는 작은 사본만 있습니다. 네트워크를 허용하지 않으면 큰 이미지를 못 받습니다.
- **필요한 크기만 요청합니다.** 썸네일에 원본을 쓰면 메모리가 금방 찹니다. 이 앱은 분석용 512px, 썸네일 200~240px, 크게 보기 1200~1600px로 나눠 요청합니다. 웹의 `srcset`과 같은 생각입니다.
- **삭제는 사용자 확인을 거칩니다.** 앱이 요청하면 아이폰이 확인 창을 띄우고, 지운 사진은 "최근 삭제된 항목"에 30일 남습니다.

## Vision — 이미지 분석

기기 안에서 돌아가는 이미지 인식 기능입니다. 사진이 서버로 나가지 않습니다.

- **특징값(feature print)**: 사진의 내용을 숫자 묶음으로 요약한 것. 두 사진의 특징값 거리가 가까우면 비슷한 사진입니다. → [알고리즘](06-algorithms.md)
- **얼굴 품질**: 얼굴이 또렷하고 눈을 떴는지 등을 0~1 점수로 줍니다. 추천 사진을 고를 때 씁니다.

## MapKit — 지도

- `Map { Marker(...); MapPolyline(...) }`: 화면에 지도, 핀, 선을 그립니다.
- `MKMapSnapshotter`: 지도를 **그림 파일로** 만들어 줍니다. 화면의 지도는 이미지로 저장이 안 돼서, 공유 이미지를 만들 때 이걸로 따로 받습니다.

## CoreLocation — 장소 이름

**역지오코딩**: 좌표(37.5446, 127.0559)를 사람이 읽는 이름(성수동1가)으로 바꾸는 것입니다. 반대는 지오코딩.

- 애플 서버에 물어보는 것이라 **인터넷이 필요**합니다. 이 앱에서 기기 밖으로 나가는 유일한 정보가 이 좌표입니다.
- **요청 횟수 제한**이 있습니다. 짧은 시간에 많이 보내면 한동안 막힙니다. 그래서 받은 이름을 파일에 저장해 두고(**캐시**) 같은 곳은 다시 묻지 않습니다.

외부 서비스에 요청할 때는 늘 두 가지를 생각합니다. "실패하면 어떻게 보여 줄까"(이 앱은 "장소 1"로 대체)와 "너무 많이 부르지 않나".

## SF Symbols — 아이콘

`Image(systemName: "pencil")`처럼 이름만 쓰면 애플이 제공하는 아이콘이 나옵니다. 아이콘 파일을 따로 넣을 필요가 없습니다. 글자 크기·굵기를 따라갑니다.
