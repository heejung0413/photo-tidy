# 알려진 문제

2026-11-16 코드 리뷰 2회(앨범 타임라인 변경분, 전체 코드)에서 나온 것. **전부 미수정**, 고칠지는 사용자 결정 대기.

## 정리 기능

| # | 문제 | 위치 |
| --- | --- | --- |
| 1 | 분석 후에 들어온, 촬영 시각이 옛날인 사진(에어드롭·메신저 저장 등)은 다시 분석되지 않는다. 기준 시각 이후만 보기 때문 | `AppModel.startAnalysis`, `PhotoLibrary.fetchPhotos(after:)` |
| 2 | 읽지 못해 건너뛴 사진도 기준 시각이 지나가서 다시 시도하지 않는다 | `AppModel.startAnalysis` |
| 3 | 긴 연속 촬영(예: 1,500장)은 한 구간이라 진행 표시가 멈추고 취소가 안 먹는다. 쌍 비교가 n² | `SegmentProcessor.process` |

## 사소한 것

- 썸네일 전부에 같은 음성 안내 "사진 크게 보기"(테스트용 이름). `accessibilityIdentifier`로 옮기는 게 맞다.
- 사진 → `TimelinePhoto` 변환 코드가 두 군데(`PhotoLibrary+Timeline`, `PhotoLibrary+Albums`)에 복사돼 있다. (시간 표시·기간 문구·좌표 키 중복은 2026-11-16에 Core로 합쳐 해결)

## 실제 기기에서 확인할 것 (미검증)

- 공유 앨범이 메뉴에 나오는지, 그 사진에 위치 정보가 있는지, 썸네일·크게 보기가 뜨는지.
- 실제 사진에서 묶기 정확도(임계값 0.5), 수천 장 분석 속도, 분석 취소.
- 일부 사진만 허용했을 때, 인터넷이 없을 때 장소 이름.
- 앨범 화면에서의 이미지 공유, 40곳 초과, 메신저로 실제 전송.
- 다크 모드.
