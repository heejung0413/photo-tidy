# 알려진 문제

2026-11-16 코드 리뷰 2회(앨범 타임라인 변경분, 전체 코드)에서 나온 것. 1·2·4·5·8번과 3·6·11번, 7번 일부는 같은 날 고쳤다(아래 "고친 것"). 9·10번도 같은 날 고쳤다. 남은 것은 3·6·7번의 일부.

## 정리 기능

| # | 문제 | 위치 |
| --- | --- | --- |
| 3 일부 | 긴 연속 촬영 구간 안의 쌍 비교가 n²(1,500장이면 약 110만 번). 취소와 진행 표시는 고쳤고, 비교 횟수 자체는 그대로다 | `SimilarityGrouper.groups` |

## 타임라인

| # | 문제 | 위치 |
| --- | --- | --- |
| 6 일부 | 받지 못한 장소 이름(인터넷 없음, 요청 제한)은 그 화면에서 다시 시도하지 않는다. 날짜나 앨범을 다시 열면 다시 묻는다 | `TimelineModel.load` |
| 7 일부 | 큰 앨범: 머문 곳 수백 곳의 이름을 차례로 다 물어 애플의 요청 제한에 걸릴 수 있다. 지도 핀도 전부 그린다 | `TimelineModel.load`, `TimelineView.pins` |

## 고친 것 (2026-11-16)

| # | 문제 | 고친 방법 |
| --- | --- | --- |
| 1·2 | 나중에 들어온 옛 사진, 읽지 못한 사진이 다시 분석되지 않음 | 기준 시각을 없애고 "분석한 사진 id"를 저장. 분석 안 된 사진이 든 구간만 다시 본다(`AnalysisPlanner`, `StoreState.analyzedIDs`) |
| 4 | 공유 이미지 준비 중 날짜를 바꾸면 내용이 섞임 | 버튼을 누른 순간 내용을 고정(`ShareOutline`, `TimelineShare.request`) |
| 5 | 직접 붙인 장소 이름이 풀림, 옆 장소 이름이 같이 바뀜 | 이름을 그 머문 곳의 **사진**에 붙인다. 이름 붙인 적 없는 머문 곳만 200m 이내 가장 가까운 이름을 물려받고, 물려받은 이름을 고치거나 지워도 원래 장소는 그대로다(`CustomPlaceNames`) |
| 8 | 화면 지도 선이 날짜를 넘어 이어짐 | 날짜별로 선을 따로 그린다(`TimelineDay.route`) |

같은 날 두 번째 리뷰(`/code-review high`)에서 나온 것도 반영했다.

| 문제 | 고친 방법 |
| --- | --- |
| 영영 못 읽는 사진 때문에 그 구간을 매번 다시 분석 | 같은 사진을 3번(`Tuning.maxReadAttempts`) 못 읽으면 포기(`StoreState.markUnreadable`) |
| 공유 이미지에 "장소 2"가 그대로 찍힘 | 썸네일을 받은 뒤, 그사이 받은 이름을 다시 채운다(`ShareOutline.retitled`, `TimelineModel.knownName`) |
| 장소 이름 파일이 깨지면 다음 저장 때 기존 이름이 사라짐 | 못 읽는 파일은 `.broken`으로 옮겨 보관(`PlaceNameStore`) |
| 화면과 공유 코드에 "보이는 날짜 목록" 계산이 중복 | `TimelineModel.displayDays` 하나로 |

같은 날 세 번째로, 보류했던 것 중 시뮬레이터와 맥에서 확인할 수 있는 것을 고쳤다.

| # | 문제 | 고친 방법 |
| --- | --- | --- |
| 3 | 긴 구간에서 진행 표시가 멈추고 취소가 안 먹음 | 사진을 한 장 읽을 때마다 진행을 알리고 취소를 확인한다. 도중에 멈춘 구간은 분석한 것으로 치지 않아 다음에 다시 본다(`SegmentProcessor.process`의 `isCancelled`·`onProgress`, `Output.wasCancelled`) |
| 6 | 날짜를 빠르게 넘기면 장소 이름이 안 붙음 | 요청을 한 줄로 세워 앞 요청이 끝난 뒤에 보낸다. 같은 곳을 동시에 물으면 한 번만 묻는다(`PlaceNameLookup`). 맥에서 같은 지오코더에 요청 3개를 겹쳐 보내 첫 번째만 답이 오는 것을 확인했다 |
| 7 | 앨범의 모든 줄을 한 번에 그림, 이름 찾기가 n² | 앨범 화면을 `LazyVStack`으로, 순번은 미리 만든 표(`TimelineModel.order`)에서 찾는다 |
| 11 | 날짜별 묶기 계산이 화면 스레드에서 돎 | 사진 읽기와 같은 백그라운드 작업 안에서 계산한다(`TimelineModel.load`) |

| 9 | 사진 수가 바뀌면 같은 앨범을 다른 앨범으로 봄 | 보던 앨범은 id로만 비교한다(`TimelineModel.albumID`) |
| 10 | 앨범 목록·열린 앨범이 실행 중 새로고침되지 않음 | 사진첩 변경 알림을 받아(`LibraryChangeWatcher`) 0.5초 잠잠해진 뒤 날짜·앨범 목록과 보고 있는 범위를 다시 읽는다. 보던 앨범이 없어지면 하루 보기로 돌아간다. 다시 읽어도 그대로인 머문 곳의 이름은 지우지 않는다 |

10번의 비용: 사진첩이 바뀔 때마다(이 앱의 삭제, 즐겨찾기 표시 등 포함) 타임라인이 사진첩 전체의 날짜와 앨범 목록을 다시 읽는다. 타임라인 탭을 한 번도 열지 않았으면 알림을 받지 않는다.

7번과 11번은 사진이 많은 앨범으로 속도를 재 보지는 못했다(시뮬레이터 샘플은 12장).

재현되지 않아 고치지 않은 것: "하루 보기에서 날짜를 넘기면 지도에 앞 날짜의 선이 남는다". 이틀 치 샘플로 날짜를 넘겼다 돌아와 봤지만 선이 그날 것으로 바뀌었다(`SmokeTests.testRouteFollowsDayWhenSwitching`).

남은 한계와 비용:

- 이름 붙인 적 없는 머문 곳은 200m 안의 다른 장소 이름을 물려받는다. 틀리면 그 머문 곳만 고치면 된다.
- 분석할 때마다 사진첩 전체 목록(정보만)을 훑는다. 새 사진이 없어도 그렇다.
- 저장할 때마다 분석한 사진 id 전체를 다시 쓴다(사진 5만 장이면 약 2.5MB). 분석 중 200장마다, 묶음을 지우거나 건너뛸 때마다.
- 직접 붙인 이름이 많고 앨범이 크면 화면을 그릴 때마다 거리 계산이 많아진다.

## 고친 것 (2026-11-18)

전체 코드를 다시 읽고 찾은 것.

| 문제 | 고친 방법 |
| --- | --- |
| 묶음의 첫 사진이 사진첩에서 사라진 뒤에는 삭제 마무리와 건너뛰기가 조용히 무시됨(묶음 id = 첫 사진 id라서 id가 바뀜). 2장 이상 남기고 지운 묶음이 목록에 다시 나올 수 있었다 | 화면이 들고 있던 묶음을 id가 아니라 **겹치는 사진**으로 찾는다(`StoreState.resolve(_:deleted:)`, `skip(_:)`) |

재현: 코어 로직에서 `prune` 뒤에 `resolve`·`skip`을 부르면 묶음이 숨겨지지 않았다(`GroupStoreTests`의 `…WhoseFirstPhotoWasAlreadyPruned`).
삭제 확인 창이 닫히며 앱이 다시 켜질 때 `prune`이 실제로 먼저 도는지는 기기에서 확인하지 못했다(어느 순서든 이제 결과가 같다).

같은 검토에서 찾았지만 고치지 않은 것:

- 웹: 좌표 범위를 검사하지 않는다(`readPhoto`). 범위 밖 좌표의 머문 곳이 앞쪽에 3곳 이어지면 이름 요청이 매번 실패해 쉬게 되고, 뒤쪽 정상 장소는 이름을 영영 받지 못한다(로직으로 재현).
- `groups.json`을 읽지 못하면 빈 상태로 시작해 다음 저장 때 덮어쓴다. 건너뛴 표시가 사라진다(`PlaceNameStore` 같은 `.broken` 보관이 없다).
- 미확인: 하루 보기 공유에서 아이클라우드에만 있는 사진의 썸네일 요청이 끝나지 않을 가능성(`PhotoLibrary.displayImages`).

## 사소한 것

- 썸네일 전부에 같은 음성 안내 "사진 크게 보기"(테스트용 이름). `accessibilityIdentifier`로 옮기는 게 맞다.
- 사진 → `TimelinePhoto` 변환 코드가 두 군데(`PhotoLibrary+Timeline`, `PhotoLibrary+Albums`)에 복사돼 있다. (시간 표시·기간 문구·좌표 키 중복은 2026-11-16에 Core로 합쳐 해결)

## 실제 기기에서 확인할 것 (미검증)

- 공유 앨범이 메뉴에 나오는지, 그 사진에 위치 정보가 있는지, 썸네일·크게 보기가 뜨는지.
- 실제 사진에서 묶기 정확도(임계값 0.5), 수천 장 분석 속도, 분석 취소.
- 일부 사진만 허용했을 때, 인터넷이 없을 때 장소 이름.
- 앨범 화면에서의 이미지 공유, 40곳 초과, 메신저로 실제 전송.
- 다크 모드.
