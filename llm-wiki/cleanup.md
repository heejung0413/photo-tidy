# 정리 기능

설계 원문: `docs/superpowers/specs/2026-11-16-photo-tidy-design.md`

## 흐름

권한 허용 → 분석 → 묶음 목록 → 묶음 상세에서 남길 사진 확인 → 나머지 삭제(아이폰 확인 창) 또는 건너뛰기.

## 묶는 규칙

1. 사진을 촬영 시각순으로 놓고 간격이 60초(`Tuning.maxGap`)를 넘으면 구간을 끊는다. 1장짜리 구간은 이미지도 읽지 않는다.
2. 구간 안에서 모든 쌍의 지문 거리를 재고, 0.5(`Tuning.distanceThreshold`) 이하면 같은 묶음으로 잇는다. A–B, B–C가 가까우면 A·B·C가 한 묶음.
3. 2장 이상인 것만 묶음.

## 추천 규칙 (`BestShotPicker.pick`)

- 즐겨찾기한 사진이 있으면 그 안에서 고른다.
- 묶음의 모든 사진에 얼굴이 있으면: 선명도 0.5 + 얼굴 품질 0.4 + 편집 여부 0.1.
- 아니면: 선명도 0.9 + 편집 여부 0.1.
- 동점이면 픽셀 수 많은 것 → 나중에 찍은 것.
- 선명도는 라플라시안 분산(경계가 또렷할수록 큼).

## 분석 진행 (`AppModel.startAnalysis`)

- 분석한 사진의 id를 저장해 두고(`StoreState.analyzedIDs`), 분석 안 된 사진이 하나라도 든 구간만 다시 본다(`AnalysisPlanner.pendingSegments`). 촬영 시각이 아니라 "분석했는지"로 판단하므로, 나중에 들어온 옛날 사진도 이웃 사진과 함께 분석된다.
- 읽지 못한 사진은 분석 완료로 치지 않아 다음 분석에서 다시 시도한다.
- 사진 목록(정보만)은 매번 전체를 읽는다. 이미지를 읽어 분석하는 것은 대상 구간뿐이다.
- 구간별로 백그라운드에서 처리하고 200장마다 저장한다.
- 삭제된 사진은 다음 실행 때 묶음에서 빼고(`prune`), 1장만 남은 묶음은 없앤다.
- 확보 용량은 추정값: 픽셀 수 × 0.2바이트.

## 알려진 한계

긴 연속 촬영에서 취소가 안 되는 문제는 [known-issues](known-issues.md) 3번. 실제 사진에서 임계값 0.5가 맞는지는 미확인.

2026-11-16까지는 "마지막으로 분석한 사진의 촬영 시각"(기준 시각)으로 증분 분석을 했다. 그 형식의 저장 파일은 묶음만 유지하고 다음 분석에서 전체를 다시 본다.
